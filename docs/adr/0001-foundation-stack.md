- Status: Accepted
- Date: 2026-10-25
- Context: Milestone M1a (spec §6, backlog F-01, F-02, F-08, F-11)

## Server-only boundary

Privileged code lives in `src/server/`. Three independent guards enforce this:

1. `import "server-only"` in every `src/server` module — the build fails if client code imports it.
2. ESLint `no-restricted-imports` blocks `@/server` from `src/components` and `src/lib`.
3. `tests/unit/architecture.test.ts` checks all of the above for every file, including any
   `"use client"` module elsewhere, and that non-public `process.env` reads stay server-side.

Each guard was verified by deliberately introducing a violation and seeing it fail.

## Environment

`APP_ENV` (local | preview | production) is derived from Vercel's `VERCEL_ENV` when not set,
so preview and production are labelled correctly without manual configuration. Public values
must use `NEXT_PUBLIC_`; secrets are added to the server schema in the milestone that needs
them.

## Consequences

- `new Date()` and similar values cannot be used during prerendering without `connection()` or
  `"use cache"`; the health route uses `connection()`.
- A nonce-based Content-Security-Policy is deferred to M1c, when auth and its scripts arrive.
  Baseline headers (HSTS, nosniff, frame denial, referrer and permissions policies) ship now.
- The holding page is `noindex` until the product name is cleared (decision D21).
